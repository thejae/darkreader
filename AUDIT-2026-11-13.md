# Dark Reader repo audit — 2026-11-13 (v4.9.135)

Read-only audit of the whole repo, done with three subagent sweeps (core engine, build/CI, background) plus an inject sweep, every finding fact-checked against source. **Rule set:** correct > safe > holds under load > tested > fast > lean; every finding has a concrete failing case; smallest fixes; prefer deletions. This file is the continuation point: fixes are being implemented in finding order #1→#20 (see "Fix log" at the bottom).

**What this repo does:** Dark Reader is a browser extension (Chrome MV2/MV3, Firefox MV2, Thunderbird, Edge, paid "plus" builds) that re-themes web pages: the content script parses each page's CSS with a custom text parser (`src/utils/css-text/**`, `color.ts`, `math-eval.ts`) and injects a generated dark theme; a background service stores settings, syncs them across devices, fetches site-fix configs from `darkreader.app`, proxies cross-origin CSS/image fetches, and on MV3 proxies `CSSStyleSheet` in the page (MAIN world, `inject/proxy.js`).

**Assumed load:** ~7M+ users; injected code runs in every tab on every DOM mutation; MV3 service workers are short-lived (force-killed at ~5 min, restarted constantly); `chrome.storage.sync` quota 8 KB/item; MV2 pages live for days.

## Must fix

### 1. Sync-storage split corrupts the live settings object — popup and per-tab updates die
`src/background/user-storage.ts:185,188` + `src/background/utils/extension-api.ts:113-117`
- **What this is:** `saveSettings` passes the *live* `UserStorage.settings` object to `writeSyncStorage`; `prepareSyncStorage` mutates its argument in place — it inserts chunk keys (`key_1a`, `key_1b`…) into the object (`:113`) and replaces `values[key]` with `{__meta_split_count: n}` (`:115-117`).
- **Problem:** once `customThemes`/`enabledFor` exceed the per-item quota (any active user), those arrays become objects in memory. `enabledFor.find(...)` (`extension.ts:711-712`), `presets`/`disabledFor` `.map/.find` in the popup (`getData`, popup site-list), and per-tab enable/disable throw TypeError → blank popup, dead site toggles. The next write re-splits the mangled object: `readSyncStorage` reassembly corrupts, sync data lost. MV2: permanent (worker never restarts). MV3 masks it by restarting the worker.
- **Fix:** `await writeSyncStorage(JSON.parse(JSON.stringify(UserStorage.settings)));` — clone before split; `prepareSyncStorage` may then mutate freely.
- **If we skip it:** data loss for every user with many site toggles; permanent popup breakage on Firefox/Chrome MV2.

### 2. Unterminated attribute selector throws on every Edge page — dynamic theming never starts
`src/inject/dynamic-theme/index.ts:777` (call at `:457`, gate `runDynamicStyle` `:522-525`; `isEdge` = Chromium + UA `edg`, `src/utils/platform.ts:39`)
- **What this is:** `document.querySelector('embed[type="application/pdf"')` is missing `]` → `SyntaxError` on every call. Every Edge page runs `isEdge ? tryInvertEdgePDF() : tryInvertChromePDF()` as the last statement of `createDynamicStyleOverrides`.
- **Problem:** the throw escapes before `watchForUpdates()` (`:524`) runs → no style-change observer, no inline-style observer, no shadow-root watcher, no `onDOMReady`, no PiP fix. `onMessage` has no try/catch → uncaught. Edge pages are themed once at load, never again.
- **Fix:** add the `]`; wrap the `isEdge ? ...` call in `try/catch`.
- **If we skip it:** Edge (second-largest Chromium share) stays permanently half-themed on dynamic sites (Gmail, YouTube).

### 3. Background `FETCH` trusts the message's own origin — cookies sent, redirect guard bypassed
`src/background/tab-manager.ts:237-267` + `src/utils/network.ts:12-14,37-39` + `src/inject/dynamic-theme/network.ts:21`
- **What this is:** the FETCH handler takes `{url, responseType, mimeType, origin}` from the message with no `sender.tab`/`sender.url` validation (`return true` for async). Cookies: `sameOrigin = origin && url.startsWith(origin + '/')` → `credentials` sent when the *message-supplied* origin matches the URL. Redirect guard runs only when `response.redirected`; inject-side guard (`network.ts:21`) is skipped when `parsedURL.origin === request.origin` (self-declared).
- **Problem, concrete case:** `evil.com` page contains `@import url("/redir.css")`; `/redir.css` answers 302 → `https://intranet.example.com/app.css` (public host, `Content-Type: text/css`). Inject-side guard skipped (self-declared origin matches), background fetches with `*://*/*` host permission, final-URL guard passes (not IP, not in `localSubDomains`, https, no port), content returns to the page. Result: a CORS bypass for any public `text/css` URL via a page-hosted redirect, and cookies go to the page's own host. Direct (non-redirected) cross-origin fetch has no background-side guard at all.
- **Fix:** in the FETCH handler, before fetch: `const frameOrigin = new URL(sender.url).origin; if (request.origin !== frameOrigin) { sendResponse(null); return; }`. (Also keep the final-URL `shouldIgnoreCors` check.)
- **If we skip it:** the extension is a fetch proxy for any page that hosts a CSS redirect.

### 4. `evalMath` cannot handle parentheses or unary minus → colors become `NaN`
`src/utils/math-eval.ts:95` (operators map, only `+ - * /`), `:64` (`stack.splice(0, 2)`)
- **What this is:** the shunting-yard engine emits `(` as a raw token; `)` merges into the last token; a leading unary operator runs `op.exec(undefined, args[0])` → `NaN`.
- **Problem, traces:** `calc(100% - (10% + 20%))` → NaN; `calc(-10% + 100%)` → NaN; `calc((0.5+0.25)*100%)` → NaN. In `color.ts:449-484` (`lowerCalcExpression`), NaN renders as the string `NaN` → `parseColor` returns null → the color silently falls back (gradients, `hsl(calc(...))`, `filter: contrast(calc(...))`). No unit-mixing check: `%` is stripped wholesale, so `calc(50% - 10px)` becomes `40%`.
- **Fix:** push a `(` marker onto the stack, pop operators until `(` at close; unary detection: operator with no left operand → negate. Reject mixed units in `lowerCalcExpression` (bail out → keep original).
- **If we skip it:** `calc()` inside colors is now common in modern CSS; a growing share of sites themes wrong. **No test exists for `evalMath`** — `tests/unit/utils/math.tests.ts` covers only scale/clamp/multiplyMatrices. Add tests with the traces above.

### 5. MV3 context menus are dead after every service-worker restart
`src/background/extension.ts:367-369` (listener registered inside `registerContextMenus`) + `:254` gate + `registeredContextMenus` in `StateManager`/`storage.session` (`:35-39,92-96`)
- **What this is:** menu items live in Chrome; the click listener is added once, inside the registration call. `chrome.storage.session` survives worker restarts (only cleared at browser shutdown), so the state gate sees "registered" and skips.
- **Problem:** after every worker death, Chrome restarts it, the gate skips re-registration → `contextMenus.onClicked` listener is never added again → right-click "Enable for this site"/"Toggle Dark Reader" does nothing — permanently, for every MV3 user.
- **Fix:** add `chrome.contextMenus.onClicked.addListener(...)` unconditionally at startup; keep the state gate only for `create()`.
- **If we skip it:** the context menu is decorative for all MV3 users.

### 6. `sendRequest` callback destructuring crashes the popup
`src/ui/connect/connector.ts:19-29`
- **What this is:** `chrome.runtime.sendMessage(payload, ({data, error}) => …)`. When the worker is dead (MV3 cold start) or the handler never replies, the callback fires with `undefined`.
- **Problem:** destructuring `undefined` throws an uncaught TypeError inside the callback; the promise never resolves → popup hangs blank at startup — the standard MV3 cold-worker path, hit by every user opening the popup after idle. Documented behavior: webextension-polyfill issue #579 (https://github.com/mozilla/webextension-polyfill/issues/579). Firefox port path rejects on disconnect (`:31-45`); Chrome path has no guard.
- **Fix:** `chrome.runtime.sendMessage(payload, (response) => { if (!response) { reject(new Error('no response')); return; } const {data, error} = response; … });`
- **If we skip it:** random blank popups on MV3, untraceable (exception swallowed in callback).

### 7. Color-scheme parser crashes past its own error wrapper
`src/utils/colorscheme-parser.ts:128` (`checkVariant` returns `undefined` after `throwError`), `:188` (`checkVariant(2, false)!` + destructure at `:189`), `:199-200` (`checkVariant(6, true)!`), interrupt check at `:192` runs after.
- **Problem:** one malformed `color-schemes.drconf` line (the config is fetched from the CDN at every extension start, `config-manager.ts:96-99`) throws TypeError inside `handleColorSchemes` → `parseColorSchemeConfig` wrapper never returns `{result, error}` → `Promise.all(...).catch` in `load()` logs "Fatality" and **all six configs, including site fixes, stay unloaded**.
- **Also:** `:138` variant check is case-sensitive: lowercase `light` accepted as a valid variant → parsed as dark scheme.
- **Fix:** `const firstVariant = checkVariant(2, false); if (!firstVariant) { return {result: null, error: ...}; }`; same at `:199`; lowercase the variant name at `:138`.
- **If we skip it:** one bad config line disables site fixes for all users until the CDN fix lands.

### 10. CORS guard self-disables after 16 redirects — imports silently stop on MV2
`src/utils/network.ts:74-146` (`MAX_CORS_HOSTS = 16`)
- **Problem:** every redirect host, including blocked ones (`:128-130`), is added to `corsHosts`; `size >= MAX` (`:135`) → all new hosts rejected; `checkedOrigins` grows (`:144`); neither set is ever evicted. A long-lived MV2 tab (Gmail, news SPA with chained `@import`) touching 16 redirect hosts → every later CSS import throws "Cross-origin limit reached" → dark theme silently misses whole stylesheets for the rest of the session.
- **Fix:** LRU eviction on both sets; don't count blocked hosts.
- **If we skip it:** unexplainable "parts of the site stay white" on long-lived MV2 tabs.

### 11. Sync turns itself off silently and permanently
`src/background/user-storage.ts:136-144` (null sync read at startup → sync off), `:189-193` (any sync-write failure → `syncSettings:false` written everywhere, local wins), logging `__DEBUG__`-gated (`background/utils/log.ts:13-18`).
- **Problem:** a transient Chrome sync hiccup (quota, offline, corrupt chunk) permanently disables sync across devices; the user has no way to know why; "settings don't sync" tickets have no signal.
- **Fix:** on write failure, log a warning and keep `syncSettings` as-is (retry on next save); flip the flag only on explicit user action.
- **If we skip it:** the most common support ticket stays invisible.

### 12. `saveSettingsIntoStorage` resolves before the write happens — lost settings on MV3
`src/background/user-storage.ts:178-201` + `src/utils/debounce.ts` (fire-and-forget `setTimeout`, discards the result).
- **Problem:** user changes a setting, closes the popup, MV3 worker dies after idle → pending `setTimeout` never runs → setting lost; callers already resolved "success".
- **Fix:** make the debounce return the pending promise (`clearTimeout; t = setTimeout(() => { resolve(write()) })`), `await` it.
- **If we skip it:** dropped theme/settings edits on MV3, un-reproducible.

### 13. Promises that never resolve in long-lived pages (images and CSS imports)

### 14. Inline-style overrides stop working in re-rendering containers after ~10 re-renders
`src/inject/dynamic-theme/inline-style.ts:369-404` (`MAX_LOOP_TEARDOWNS = 10`, `parentHadTeardown` WeakMap never decremented/expired), reset only from `stopWatchingForInlineStyles` (`:406-409`).

## Verdict
The CSS/color engine core is in good shape (16 suites / 73 unit tests pass locally; the parser's string-blindness and `evalMath` gaps are the real risk). The dangerous seams are the MV3 lifecycle (context menus dead, popup requests crashing, promises that never resolve) and the settings-storage path (sync corruption, silent sync-off, lost writes). Fix 1, 2, 5, 6 first — they hit every MV3 user and all Edge users. Tier two: the FETCH trust boundary (#3) is the only security finding. Test gaps that matter: `evalMath` zero tests, `tests/unit/background/**` zero files for 18 modules, CI `paths-ignore` skips site fixes.

**Lean:** -190 lines, -0 dependencies possible. Runtime deps are one package, `malevic@0.20.3` — nothing removable.

**Not checked:** Thunderbird/Safari/`plus`/API builds beyond reading; browser (puppeteer) and karma inject tests not executed locally (only `test:unit` ran); signed rebuild and release-xpi contents (unsigned-ship claim #19 is from the code path, not a built artifact); external GitHub CI status; `deno.json` task runs; release xpi zip contents counted by the build agent (87 entries, 0 META-INF — unverified claim).
